# Orchestra 任务通信与多节点契约

## 用户目标与完成条件

保留现有控制器、执行、不可变验收、独立审核和集成机制，支持网页/手机发起一个或多个任务；同机及另一台机器上的 Agent 经控制器协作；运行中查询现状或补充信息；刷新、重连后继续查看完整过程与可读结果。

阶段顺序不改变最终范围：先任务运行中通信，再远端节点，再统一跨设备入口。阶段完成不是全目标完成。真实另一台机器和实际手机验收单列，协议替身、本机多进程和窄屏模拟均不是该项完成证据。

## 不变量

- 唯一任务真相仍在现有 autonomy.sqlite3、hash-chained events、Journal 和 verifier 中。消息/投递回执不是任务 PASS。
- 开页面、问问题、发补充资料不派发新的工作、不改变 objective、checks、acceptance_hash、已有方案或停止状态。原生会话和聊天提案仍受现有确认与派发闸门控制。
- 开工前 draft 的冻结行为保留。运行中消息走独立 mission inbox，不解除已绑定草案的限制。
- 查询、消息输入和产物显示遵循现有身份边界、大小限制与脱敏规则；错误显示可追踪诊断，未知执行不盲目重发。
- Lead/独立审核为明确 claude-opus-5-5，执行者为明确 gpt-6.1-sol。配置与 runtime attestation 分开。
- 所有失败尝试、日志和测试工件保留。删除只用 /usr/bin/trash 绝对路径，不使用永久删除或破坏性 Git。

## 1. 运行中通信

1. 任务对话提供独立、持久、可增量读取的消息入口；每次提交有 request_id。重复相同请求返回同一回执，冲突请求明确报错，浏览器重试不重复处理。
2. `/btw` 查询从控制器当前状态返回人可读的进展、卡点、最近结果，并带快照/事件定位。已停止、暂停、UNKNOWN、失败、未验收等状态如实呈现，不新调模型、不增加原生执行。
3. 普通消息作为补充资料，持久提交后显示“已收到”。当前运行原生 turn 不伪造已接收；下一次符合条件的 Lead/worker 派发明确把资料绑定到调用，记录消息 ID、run key、内容 hash，才显示“已应用到该调用”。这不是模型已遵循或任务已完成的声明。
4. 消息接收与派发并发时，冻结调用上下文：已绑定资料属于该调用，之后的新资料留给后续边界。不改变已冻结 prompt 或未知调用，不重复派发。
5. 重启后保留消息历史、查询答案与应用记录；查询和读回均不启动任务。支持多任务独立信箱，资料不跨任务泄漏。
6. 同一网页保留任务运行时输入框，展示资料处理状态、进展与结果；安全地渲染文本、中文 IME、窄屏输入和重连。

## 2. 远端节点

- 控制器管理节点身份和权限，Agent 主动领取预先批准的任务；远端不接受任意 shell 指令或自行修改验收。
- 任务身份、workspace/input manifest、原生调用 reservation、领取租约、心跳与回执持久化。重复领取/重连复用同一任务身份；失联的执行先标未知并核对，不凭超时复制执行。
- 产物上传限定任务命名空间和白名单路径，验证大小、路径、hash 与所属调用。验收、独立审核及集成由控制器保持原有闸门。
- 本地与远端共用任务消息/资料机制。凭据留在各机器自己的环境，网页、日志、产物与跨节点资料不携带私人凭据。
- 实际第二台机器完成至少一个子任务并返回经核验产物；与本机任务通过依赖协作，验证断线/重连不重复执行。

## 3. 网页/手机统一入口

- 一个任务页面同时包含对话、阶段进展、图、证据和最终结果，研究/工程后端保留各自真相，不靠浏览器合成验收。
- 手机入口有明确身份与访问路径；默认本机边界保持，外网入口显式配置，不暴露无认证控制 API。
- 最终报告先回答“做成了什么/结论是什么/依据是什么”，再提供过程与专业证据。未知、待验和失败不粉饰。
- 实际手机发起任务、运行中 `/btw`、补充资料、刷新/重连后读回历史与结果；与第二台机器执行记录关联。

## 固定验收集合

- A1 消息收取、重复请求、冲突、输入边界、任务隔离和 hash chain。
- A2 `/btw` 对运行/等待/暂停/停止/UNKNOWN/完成状态的如实输出与零派发。
- A3 接收与应用的区分、冻结 prompt 的并发边界、未知 reservation 的保护。
- A4 后端/网页多任务消息与重启读回，原有 bound draft 冻结测试继续通过。
- A5 原有执行/审核/集成、预算、停止、RSI 与报告回归继续通过。
- A6 节点身份、领取、租约、断线核对、回执及产物验证的正常与失败路径。
- A7 本机+真实第二台机器协作，重连不重复执行，独立审核与集成证据。
- A8 实际手机的创建、查询、资料补充、重连读回与统一结果展示。

每项记录测试或实际运行证据及尚待事项。执行结果出现之后不收窄这些完成条件。
