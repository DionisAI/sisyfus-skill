# 聊天驱动的 RSI 编排验收

本次扩展位于 `codex/techlead-web-rsi`，沿用中文浅色聊天页面，不新增 RSI
配置表单。已安装的发行版与其他任务目录保持原样。

## 本轮合同

1. 用户在聊天里明确开启 / 关闭 RSI、指定固定评估集，以及选择只评估或按
   原门槛自动晋升。目录缺项可用后续对话回答；普通讨论、假设和助手文本不
   授予配置能力。模型的规划与回复仍是只读建议。
2. 配置由控制器处理并保存回执。目录应与工程和控制目录独立，拒绝符号链接；
   只读 manifest 元数据与数量，spec 使用文件路径引用；不打开任务、检查
   脚本或 holdout 文件，不接受清单里内嵌的案例定义。
3. manifest SHA256 进入待确认合同；开工和配对派发前重新核对。评估集路径
   从原生规划消息中隐去，但同条消息的其他需求保持可见。配置变更撤回旧
   确认；任务成功绑定后不误报撤回确认。
4. 目录有效不是来源独立或工程验收成功的证明。固定工程验收、角色配置和
   已批准预算保持原合同。有限父预算会隔离 RSI 子试验，不自动放宽限制。
5. 聊天配置不创建执行任务、不派发 Sol。用户审阅完整方案与 RSI 范围并明确
   确认后，复用现有 MissionHub / LeadMission，不新增任务真源数据库。
6. 原有固定测试、独立 Opus 审查、集成验证、UNKNOWN 不重发和停止控制保持
   生效。配对评估仍使用有证据的候选、冻结 baseline/candidate 和独立 holdout。
7. 网页从核心快照展示每个 search / holdout 案例的真实调用数、判定依据和
   当前策略。缺失证据不是零，ELIGIBLE 不是晋升，历史晋升不是当前采用，
   零收益保持旧策略；不宣称模型权重或能力提升。完整批准目标在折叠区保留。

## 证据与边界

本地回归保留目录、失败记录和页面脚本断言。真实网页验证使用独立轮询工程
与评估案例，不覆盖源工程；原始模型回执、任务数据库、输入哈希、截图与
最终 readback 位于忽略的 `artifacts/techlead/web-rsi-20261005/`。

以该目录的交付回执记录最终测试数、真实四臂完成状态、晋升结论和源码评审
状态，不把本文件当成实时状态数据库。工程任务里的 Opus 验收，与本次
控制器源码的独立代码评审分开记录。

普通新项目的固定验收文件自动生成不在本轮范围；这里复用已批准工程验收，
不通过借用无关演示检查来绕过准备门槛。
