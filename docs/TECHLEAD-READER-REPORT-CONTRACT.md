# Reader-first research reports

## Product contract

A report answers the operator's question, not the controller's acceptance check.
Lead prepares a plain-language, evidence-linked narrative: the question, direct
answer, measured result, conditional calculations, limits and meaningful next
measurement. The process explains what was investigated, what was found and why
it matters. Status codes, repetition rules and invocation receipts belong in a
collapsed technical layer or the audit tab. Missing prose is exposed as missing
prose; completion never manufactures an answer or profit.

The current Entropy × XYZ case must state: 10 minutes of public observation,
zero completed model cycles, one partial maker fill with residual inventory,
no live orders and no daily-profit estimate. Hypothetical volume-to-profit
arithmetic is labelled conditional and uses the four-fill volume denominator.
The discovered dual-taker implementation is distinct from the user's unidentified
original poster and from our separate maker–taker experiment.

## Scope and binding

Reuse the existing `i18n.json` presentation sidecar. It is not event-chain truth.
Do not change Python projection/state/HTTP functions, task, events, metrics,
acceptance, historical report artifacts or the frozen graph fingerprint tests.
Only Observatory template prose/layout/JavaScript and new report sidecar data
are changed. Preserve unrelated dirty chat/RSI work.

`report.reader` schema `sisyfus.reader-report.v1` contains:
- `basis`: exact `snapshot_hash` and `event_count`;
- `language`, `title`, `question`, `answer`, `scope_note`;
- `sections`: headings, paragraphs, optional labelled tables and notes;
- `process`: title, what was done, finding, implication;
- `claim_takeaways`: each has the exact raw status and a human explanation;
- `event_notes`: event sequence, exact event type, feed/caster text;
- `sources`: readable label and HTTPS or confined local artifact link.

Validate schema and snapshot/event binding before showing the narrative.
Malformed or stale narrative shows an explicit diagnostic and technical evidence,
not cached old financial claims. Per-claim explanations require matching status
and latest-frame context; replay prefixes never receive the final conclusion.
Event notes bind to the exact event type. Strings are escaped, unsafe links
disabled, tables scroll inside their container and print retains readable prose.
Language fallback is labelled as the report's original language.

## Frozen acceptance before implementation

1. Existing 73 graph/research/live regressions and immutable truth fingerprints
   pass without editing their expectations.
2. New focused tests verify schema/staleness/missing-report diagnostics,
   malicious text/link escaping, historical-frame fencing, exact event typing,
   table containment markup and conditional-profit denominator arithmetic.
3. Actual browser: report begins with question/answer, not PASS counts; economics
   tables and research process readable at 460px and wide view; graph/inspector,
   replay and audit remain usable; no JS errors.
4. Fresh native Opus Lead review of the plan and an independent read-only native
   Opus review of the implemented report/evidence. Controller integration is a
   separate gate; no worker/trading dispatch or RSI promotion.
5. Preserve original evidence and failures; publish an updated live report with
   source/data integrity receipts and a final screenshot. Stop when complete.
