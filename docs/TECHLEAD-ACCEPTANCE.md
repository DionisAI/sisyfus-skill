   specifications, dependency graphs, scoped write ownership and acceptance.
2. Sol 6.1 executes implementation tasks; independent Opus 5.5 review consumes
   frozen specifications, candidate changes and real deterministic evidence.
3. Lead diagnoses specification/architecture/dependency/implementation/environment
   failures and issues versioned repair or decomposition decisions repeatedly.
4. Controller supports real parallel work, conservative conflict detection,
   explicit integration into a candidate project and whole-project acceptance.
5. Default aggregate budgets are unlimited; optional configured caps work.
   Single-call limits, pause/stop and uncertain-execution fencing remain active.
6. Recursive improvement candidates change versioned Lead procedures/policies;
   frozen baseline/candidate comparisons and independent holdout evidence gate
   promotion and rollback. Improvement history feeds later Lead invocations.
7. Browser console can create/select missions, configure explicit role models,
   submit objectives/specifications, start, pause/resume/stop and inspect graph,
   diagnoses, attempts, reviews, integration and improvement evidence.
8. Lifecycle is restartable without duplicate unknown calls or erased history;
   receipts distinguish requested model, actual model and missing telemetry.
9. Focused regressions, relevant existing regressions, real-model positive and
   deliberately incorrect-output checks, and actual browser workflows pass.
10. User gets a durable source checkout, runnable CLI/console entry, documentation
    and final requirement-by-requirement evidence. Global installation activation
    is a separate gated operation; do not edit a versioned release in place.
