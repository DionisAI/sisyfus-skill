# Sisyfus v0.9.0

Released 2026-10-04. This release integrates PR #2 (versioned updates), PR #3
(Research OS) and PR #4 (native-worker mission control).

## Included

- Versioned source installation, Engine/Skill activation through one current
  link, verified release archives, update status/checks and rollback.
- Opt-in Research OS: evidence-gated scheduling, shared-budget portfolios,
  bounded SOP/policy experiments and support-limited replay. Existing verifier
  contracts, independent evaluation and holdouts are unchanged.
- Opt-in native Codex App Server and Claude Code CLI drivers, initial task-DAG
  planning, dependency-gated parallel attempts, bounded feedback repair,
  durable invocation receipts and conservative unknown-result handling.
- Local authenticated Mission Control: task DAG, retained failed attempts,
  native events, evidence inspector, pause/resume and supported attempt controls.

## Integration fixes

- The dependency-free installer now routes `workers`, `os`, `update` and legacy
  commands through the unified entry point.
- Native mission controllers register their independent state directories and
  hold a shared installation lock. Update/rollback refuses activation during
  a running controller; unknown receipts and unreadable state also block it.
- Current and previous release directories cannot be destroyed by an in-place
  identity-conflicting rebuild. Generated bytecode is excluded from integrity
  hashes and installed launchers do not generate it.
- GitHub authorization is limited to the configured API origin and stripped
  on cross-origin download redirects. Archive extraction has size/count limits.
- Narrow-screen grid overflow and JavaScript prototype-key collisions are fixed.
- Canonical/package versions, Skill payload and installation pins are aligned.

## Install or update

Existing versioned installs:

```bash
sisyfus update --check
sisyfus update --version 0.9.0 --yes
```

An older install without the `update` command needs the current installer once:

```bash
curl -fsSL https://raw.githubusercontent.com/DionisAI/sisyfus-skill/main/install.sh | bash -s -- --version 0.9.0
```

Restart the coding-agent session after upgrading so the installed Skill reloads.
Do not override active-work protection during an active or unresolved mission.
Rollback requires a previous versioned installation; a first install has none.

```bash
sisyfus workers doctor
sisyfus workers demo --directory /tmp/sisyfus-native-demo-new
sisyfus workers serve --directory /tmp/sisyfus-native-demo-new/control --open
```

Use a new demo directory. The demo uses deterministic native-protocol fixtures,
not authenticated Codex/Claude calls. See `docs/native-workers.md` for real-host
configuration and `docs/research-os.md` for opt-in research control.

## Validation and scope

The release pipeline gates publication on Python 3.11/3.12/3.13 regression
suites, Chromium console tests, packaged-source installation and update/rollback
checks. Build manifests and checksum files identify the exact source commit.

A native process finishing is not a verifier PASS. Offline fixtures validate
coordination and recovery, not real-provider compatibility, model savings,
scientific productivity or cross-task recursive improvement. No benchmark
advantage is claimed and no evaluation criteria were weakened.

Native workers remain an opt-in, trusted-local POSIX pilot. Directory copies are
not a hostile-code sandbox. Claude live steering, provider-side unknown-turn
reconciliation, automatic source merge/deployment, general graph evolution and
learned native-agent routing remain unsupported. Invocation limits are not hard
provider-dollar caps. The console is loopback-only; no public endpoint is enabled.
